## 触发条件

1. 用户要求对比多个框架/工具/产品，并分别分析若干固定维度
2. 报告结构包含「分框架章节 + 横向对比章节 + 结论」
3. 检索结果中部分框架在某个维度上仅有标题级或摘要级证据

## 输入要求

1. user_goal 中列出的对比对象与对比维度
2. 各框架检索得到的 evidence 卡片（含 title/summary/source_id）
3. completion_contract 中 required_section 与 report_consistency 要求

## 步骤

1. 先按「框架 × 维度」建立证据矩阵，每个单元格标注：有直接支持证据 / 仅有标题或摘要级证据 / 无证据。只有第一类单元格才允许在正文写出机制性断言。
2. 分框架章节中若某维度判定为证据不足，必须显式写出「现有证据不足以展开」并说明缺什么；该缺口必须在横向对比章节被同样保留，禁止在对比章节升级为确定性结论。
3. 横向对比中的每条断言必须引用直接描述该机制的证据；仅含标题或摘要的对比类文章只能用于「存在差异」这类元层面表述，不得作为具体机制断言的唯一依据。
4. 撰写结论章节前，回读引言中承诺的章节结构，逐条核对是否已产出对应内容；若某承诺因证据不足无法兑现，须在结论中显式说明原因并调整表述，不得留空或只写运行说明。
5. 摘要必须覆盖全部对比对象，不得只聚焦其中一个框架；摘要中的每个机制性表述须与对应分框架章节的结论保持一致。

## 允许工具

1. tavily_search

## 失败回退

1. 若某维度证据始终不足，则在报告中以「证据缺口」小节集中披露，并在结论中说明该维度不参与选型判断，而非用推断填补。

## 反模式

1. 在分框架章节写「证据不足」，却在横向对比章节写出「状态随消息交互自然累积」「侧重流程层面的状态持久化」等确定性机制断言
2. 用一篇框架对比文章的标题/摘要作为具体工具调用机制断言的唯一引用
3. 引言承诺「最后给出结论与选型建议」，结论章节却只保留运行说明
4. 摘要只总结其中一个框架，与报告标题声明的对比范围不一致
5. 把「适用场景建议」写成无证据支撑的推断，却挂上仅含标题的对比文章引用

## 停止与降级条件

1. 当某框架某维度在证据矩阵中连续两轮检索仍为「无直接支持证据」时，停止该单元格的进一步检索，转为显式披露缺口
2. 当横向对比章节出现无法用直接证据支撑的断言时，停止撰写该段并回退到证据矩阵核对
3. 当预算接近上限且结论章节尚未撰写时，优先用已确认证据完成结论，不再新增检索

## 验证方式

1. 逐段核对：横向对比章节中每条机制性断言，其引用证据的 summary 是否直接包含该机制描述
2. 一致性核对：分框架章节标注为证据不足的维度，在横向对比章节中是否仍保持不确定性表述
3. 结构核对：引言承诺的每个章节（含结论与选型建议）是否非空且含实质内容
4. 范围核对：摘要是否覆盖全部对比对象

## 已知限制

1. 仅覆盖 web 检索来源，无法验证官方文档版本差异
2. 证据矩阵依赖检索返回的 summary 质量，summary 截断时可能误判为「无直接支持」
3. 不适用于单框架深度分析或非对比型报告任务
